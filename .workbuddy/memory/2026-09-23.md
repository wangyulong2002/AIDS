**关键根因（复用价值高）**
1. `fastapi 0.14x` 的 `include_router` 返回惰性 `_IncludedRouter`（**无 `.path` 属性**）→ 遍历 `app.routes` 会静默漏掉全部子路由。断言/工具一律改「发请求」或递归展开。
2. Windows 上 `subprocess(["bash", ...])` 的**裸名**会被 CreateProcess 先解析到 `System32\bash.exe`（WSL 启动器），被安全策略拦成 **UTF-16 的「拒绝访问」**，经 text 解码后伪装成 `UnicodeDecodeError`。改用 `shutil.which("bash")` 的绝对路径即可。HANDOFF §8.6 把它记作「编码问题」，实为路径解析问题。
3. 本机沙箱：`pip install` 会因 `_check_bulk_delete_guard`（清 HTTP 缓存）失败 → `--no-cache-dir` + 脱离沙箱；pytest 结束时清理 `pytest-of-<user>` 会触发同一守卫并**吞掉 summary** → 用 `--basetemp=<独立目录>` 规避。
4. `py` launcher 在本机不可用，用 managed `C:\Users\heart\.workbuddy\binaries\python\versions\3.11.9\python.exe` 建 venv（Windows 布局，已替代原 Linux 版 `.venv`）。
