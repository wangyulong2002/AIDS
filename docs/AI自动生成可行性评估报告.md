## 0. 结论

**能做，但形态不是「一句话生成整个项目」，而是「门禁闭环下的逐任务生成」。**

| 判断 | 内容 |
|---|---|
| 可自动化部分 | 剩余 87 项中约 **80% 的实现工作**（≈ 135 / 168 人天）可由 AI 独立完成并自证 |
| 不可自动化部分 | ≈ 20%：外部凭据、真机压测结论、AI 效果评测、答辩叙事、范围裁决 |
| 成立前提 | §4 的 5 个前置条件必须先在 T1 内补齐（其中 2 项是「现在就能做」的） |
| 主要依据 | 规格已冻结且可机器校验；门禁可当编译器用；任务行本身就是带验收标准的 prompt |
| 一句话 | **不是 AI 变强了，是这个仓库把「验证」变便宜了**——这是可行性的真正来源 |

## 4. 五个前置条件（不满足则「能生成」≠「能完成」）

### B1 环境边界：不要跨 WSL/NTFS 边界（今天就能解决）

本 IDE 的 shell 是 WSL，而仓库在 `F:`（NTFS）。`HANDOFF.md` 实测跨边界读文件慢 **31.5 倍**、命令执行慢约 **20 倍**。
→ **执行约定**：一律用 Windows 布局解释器 `.venv/Scripts/python.exe`，禁止 `/mnt/f/...` 路径。

### B2 三个服务镜像从未端到端构建过（T1 内必补）

`DEP-02` 自述「因本机工具链拉取超慢，三个 Python 应用镜像**尚未端到端构建验证**」；compose 的 9 个服务**全是中间件**，不含应用服务；CI 的 smoke 只跑 `compose config`，**不 build**。
→ AI 写完 T1 代码后的**第一次 `docker build` 是当前最大的未知数**，必须作为 T1 出口判据之一。

### B3 门禁是「文档↔代码」门禁，不是「业务正确性」门禁

已有实证：`BE-02` 的生成器曾因正则写成 `[^,]*` 让 10 个含逗号注释的列整体消失（419→409），而 `gen_orm_models.py --check` **全程绿灯**，靠独立解析器写的契约测试才抓住。
→ **铁律的执行方式**：每个任务先补不变量/接口测试（`tdd` skill），再实现。否则 AI 会稳定产出「门禁全绿但业务错」的代码。

### B4 AI 服务的外部依赖不可离线验证

`AI-02` 需要 Ark Key 与日预算保护，真实模型效果无法离线验证（Milvus 已可本地冒烟）。
→ 需要「本地桩 + 线上小样本」双通道，并按 `PRD §9.7` 建评测集。

### B5 范围与工期需人裁决

`TASKS.md §工作量对账` 已自认：T1~T6 估算 ≈168 人天，而计划容量仅 80 人天（**2.1 倍缺口**），且单人无法靠并行消化。
→ 这恰恰是 AI 生成的最大收益点，但**必须先定 A/B/C 中哪条**，否则 AI 会在错误范围上做正确的事。

## 6. 推荐执行方案

### P0 先造治具（1 个会话，收益最高）

1. **项目专属 skill**（`skill-creator`）：`aids-task-runner` —— 输入 `TASKS.md` 的一行编号，自动完成「读依赖 → 写失败测试 → 实现 → 跑四项 `--check` + `pytest` + `ruff` + `pyright` → 生成提交信息」。
2. **环境自检向导**（`wizard`）：venv 解释器、compose 容器、`DATABASE_URL` 指向 `aids_shop_test`、四项门禁基线。
3. **补 B2**：让 CI 的 L3 真的 `docker build` 三个镜像，把「第一次构建」前移到 P0。

> 判据：对 `BE-03` 完整跑通一轮「红 → 绿 → 提交」，且门禁四项 `--check` 与全量 `pytest` 保持绿。

### P1~P6 按梯次推进

每梯次出口 = 「`TASKS.md` 梯次出口判据」+ 全量 `pytest` 绿 + 四项 `--check` 绿 + `docker build` 成功 + 一次 `code-review`（双轴）。

| 阶段 | 范围 | 预期产出 |
|---|---|---|
| P1 | T1 剩 10 项 | 登录拿到 Token（可被 AI 服务验签）、Mock 收银台可访问、三镜像可 build |
| P2 | T2 18 项 | 注册登录 / 浏览 / 搜索 / 购物车（含 50 TPS 无超卖证据） |

## 8. 一句话结论

**这个项目是「AI 自动生成」的优良样本：规格冻结、任务带可执行验收、门禁真会长牙。**
**因此结论是「能完成」，但成立条件是三件事——先造编排治具、先裁决范围、每个任务先写会失败的测试。**
**它不会自动变成好项目；它会把「差」的地方精确地变红。**
